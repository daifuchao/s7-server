# 排错：`DB5.INT356` 读出来是 `"BAD 255"`

## 结论先说

`"BAD 255"` **不是读到的数据值 255**，而是客户端（nodes7 系）返回的**质量码**：

| 质量码 | 含义 |
| --- | --- |
| `0xC0`(192) | GOOD，读取成功 |
| `0xFF`(255) | **BAD，这一项没有取到有效值** |

所以 `BAD 255` = **"这一项读取失败"**，值本身不存在。

nodes7 源码里只有一处产生这个字符串：

```js
// node_modules/nodes7/nodeS7.js
theItem.qualityBuffer.fill(0xFF);          // 初始化为 255（BAD）
...
theItem.value = theItem.badValue();
theItem.quality = 'BAD ' + theItem.qualityBuffer[thePointer];   // → "BAD 255"
```

只有该项被成功解析后才会 `qualityBuffer.fill(0xC0)`。**看到 255，说明根本没解析成功。**

---

## 实测复现：DB5 长度不够 → 必然 BAD 255

用同一份代码、同一个客户端，只改 DB5 的容量：

| 配置 | `DB5,INT356` 结果 | 服务端日志 |
| --- | --- | --- |
| DB5 = **300** 字节 | `"BAD 255"`，`bad = true` | `ERR:0x05(越界，需要 358B，当前长度 300B)` |
| DB5 = **1024** 字节 | `0`，`bad = false` | `DB5.DBB356[2]=OK` |

复现命令（模拟"真实 PLC 的 DB5 只有 300 字节"）：

```bash
# 造一个 DB5=300 的临时配置
python3 -c "
import json
d=json.load(open('config/default.json'))
for db in d['dbs']:
    if db['number']==5: db['size']=300
d['persistence']={'enabled':False}
json.dump(d,open('/tmp/config-db5-300.json','w'),indent=2)
"
node src/index.js --config /tmp/config-db5-300.json --port 1116
```

服务端日志会直接写明原因：

```
[READ ] 读取 2 项: DB5.DBB100[2]=OK, DB5.DBB356[2]=ERR:0x05(越界，需要 358B，当前长度 300B)
```

> `INT356` 需要第 **356、357** 两个字节，所以 DB 至少要 **358 字节**。

---

## 为什么"在模拟器上能读"

因为两边数据块的**实际长度不一样**：

| 项目 | DB5 实际大小 | `INT356` 是否在范围内 |
| --- | --- | --- |
| 模拟器（本项目） | **1024 字节**（配置里写的） | ✅ 能读 |
| 你的真实 PLC | 取决于 TIA 里 DB5 定义了多大的变量 | ❓ 很可能没有 356 字节 |

**DB5 的"大小"不等于"你用了几个变量"**：在 TIA Portal 里打开 DB5，看最后一行的 **Offset**，那个值才接近真实长度。如果 DB5 里最大偏移只到 `DBW20`，那整块可能只有 22 字节——读 356 必然越界。

## 6 类原因，对照服务端的返回码排查

| 返回码 | 含义 | 常见原因 | 处理 |
| --- | --- | --- | --- |
| `0x05` | 地址越界 | **DB5 没有 356 字节**（最常见） | 把 DB5 做大，或改读实际存在的地址 |
| `0x0A` | 对象不存在 | DB5 没定义 / 是"优化的块访问"（无绝对地址） | DB 属性里**取消"优化的块访问"** |
| `0x03` | 不允许访问 | CPU 未允许 PUT/GET | CPU 属性 → 防护与安全 → 勾选"允许来自远程伙伴的 PUT/GET 通信访问" |
| `0x07` | 数据类型不一致 | 请求长度和地址类型不符（如按 4 字节读一个 2 字节变量） | 客户端地址写对：INT = 2 字节 |
| 客户端超时 | 报文没到/没回 | 端口错、PDU 太大、防火墙 | 单点读测试 + 抓包 |
| `0xFF`（成功）但客户端仍 BAD | 客户端解析问题 | 一次读多项时某项失败导致指针错位 | 单独读这一项验证 |

## 排查步骤（从快到慢）

### 1. 只读这一个地址，不掺杂其他变量

```js
const conn = new nodes7({ silent: false });   // silent:false 看详细日志
conn.initiateConnection({ port: 102, host: '192.168.0.10', rack: 0, slot: 1 }, (err) => {
  if (err) return console.log('连接失败', err);
  conn.readItems(['DB5,INT356'], (bad, v) => console.log('bad =', bad, v));
});
```

- 如果**单项也 BAD** → 就是这一项本身的问题（地址/长度/DB 属性）
- 如果**单项 OK、多项 BAD** → 是"某项失败导致整包/指针错位"，需要拆包读或检查是否有越界项

### 2. 换个地址做对照

```js
conn.readItems(['DB5,INT0', 'DB5,INT356'], ...);
```

- `INT0` OK、`INT356` BAD → 明确是**越界/地址不存在**
- 两个都 BAD → 是**连接或 DB 级问题**（优化访问、PUT/GET、DB 号错）

### 3. 看服务端日志（本项目）

```bash
node src/index.js --port 102 --dump --verbose
```

```
[READ ] 读取 2 项: DB5.DBB356[2]=ERR:0x05(越界，需要 358B，当前长度 300B)
>> PDU: 32 01 00 00 00 02 00 0e 00 00 04 01 12 0a 10 02 00 02 00 05 84 ...
<< PDU: 32 03 00 00 00 02 00 02 00 04 00 00 04 01 05 00 00 00
                                                          ↑ 返回码 0x05 = 地址越界
```

### 4. 真实 PLC 上看三件事

| 检查项 | 位置 | 要求 |
| --- | --- | --- |
| DB5 实际长度 | DB5 打开后看最后一行 Offset | ≥ 358 字节 |
| 是否为非优化访问 | 右键 DB5 → 属性 → 取消"优化的块访问" | 必须取消 |
| PUT/GET 是否允许 | CPU 属性 → 防护与安全 → 连接机制 | 勾选允许 |

> TIA 的**监控表**能读到 `DB5.DBW356` 只说明"PLC 内部有这个地址"（监控表走的是符号/内部访问），**不代表第三方 PUT/GET 一定能读**——两者权限不同。

### 5. 抓包看返回码（最权威）

Wireshark 过滤 `tcp.port == 102`，找到 Read Var 的响应，展开 `Data → Item 1 → Return code`：

- `0xFF` 成功
- `0x05` 地址越界 ← 你的情况大概率是这个
- `0x0A` 对象不存在

## 针对你这个场景的建议

你之前的心跳设计是：

```
客户端写 DB6.INT372 = N  →  服务端读 N+1 写进 DB5.INT356
```

`DB5.INT356` 这个**偏移 356** 只在模拟器里成立（因为模拟器把 DB5 配成了 1024 字节）。如果要在真机上用，**必须确认真机 DB5 里真的有 356~357 这两个字节**，否则：

- 读 → 0x05 → 客户端显示 `BAD 255`
- 写 → 0x05 → 客户端显示"写值失败"

两种现象其实是**同一个原因**（地址越界），这也解释了你前面遇到的"心跳写值一直失败"。

**改法二选一**：

1. 在 TIA 里把 DB5 做大（或把心跳变量放在 DB5 已有的空闲区），记下真实偏移，把客户端和规则里的 356 改成真实地址；
2. 用模拟器联调时，把 `config/default.json` 里 DB5 的 `size` 调到足够大（本项目默认 1024）。

## 顺便：本项目已修的一个相关问题

如果配置里 DB 的 `size` 小于 `init` 里的地址（例如 `size: 300` 但写了 `"INT356": 0`），旧版本会直接抛异常导致**服务起不来**：

```
RangeError [ERR_OUT_OF_RANGE]: The value of "offset" is out of range. It must be >= 0 and <= 298. Received 356
```

现在改为**跳过该初始值并输出警告**，服务照常启动：

```
[WARN ] DB5 的初始值 INT356 需要 358 字节，但 DB 只有 300 字节，已跳过
[WARN ] 忽略逻辑规则（目标地址超出 DB5 长度 300）: 心跳1：写 DB6.INT372 → DB5.INT356 = 该值 + 1
```

这样配置写错时，启动日志会立刻告诉你"哪个地址超了、差多少"。
